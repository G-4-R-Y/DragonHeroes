# Research track: live-content-architecture

## Summary
Data-driven content (1): The PoE/Warframe-scale pattern is to define all gameplay content as pure data with stable string IDs and heavy indirection: PoE's internal tables (visible via the community RePoE export) separate base_items, mods, stats and tag-based spawn weights, so a new item/mod is a data row, not code; Warframe exposes its actual internal content as "Public Export" — LZMA-compressed, content-hashed JSON manifests on a CDN where every item has a uniqueName and the index hash changes each update, letting clients pull only changed manifests. For Godot 4 (current stable is 4.6, released Jan 2026), the native mapping is custom Resource (.tres) definitions for design-time authoring, weekly drops shipped as PCK packs loaded with ProjectSettings.load_resource_pack(), and 4.6's new partial-resource patch system that drastically shrinks update downloads. Two hard constraints: .tres/.res files can embed scripts, so anything downloaded at runtime should be pure data (JSON or script-stripped packs), and because combat is server-authoritative the server must own the canonical stat tables — clients should present a content-version hash at login and the server should reject mismatches, which also lets you hotfix balance numbers server-side without a client patch.

ECS and world architecture (2, 3): Godot is deliberately not an ECS engine — the official position is that nodes are thin interfaces to data living in the engine "servers," and the sanctioned high-entity-count path is composition (data in Resources, behavior in small nodes) plus dropping to RenderingServer/MultiMesh and PhysicsServer2D directly for projectiles and mob crowds (developers report thousands of moving bullets at 60fps this way, versus hundreds with nodes). GDScript ECS frameworks (GECS, godot-ecs) exist but are organizational only; real data-oriented performance requires a compiled language, which for this game argues for a headless, data-oriented authoritative server process (GDExtension C++/Rust, or a standalone sim — 4.6's LibGodot makes embedding feasible) with the Godot client rendering replicated snapshots. For the infinite world, the proven stack is: deterministic layered noise with seed-consistency and constant-time random access (same seed + coords → same output), on-demand chunk generation, and delta persistence. Valheim demonstrates the cleanest persistence split — the .fwl stores just the seed and the base world is always regenerable, while the .db stores only player modifications (terrain edits, buildings, items); Minecraft's Anvil format shows the on-disk mechanics (32×32-chunk region files, sector-offset headers, zlib-compressed chunk records, per-chunk timestamps) and, critically for weekly biome drops, the practice of stamping chunks with generator version so new content generates only in virgin space with blending at seams. Noita's 64×64-pixel chunks with per-chunk dirty rectangles and multithreaded falling-sand sim are the reference if you want destructible pixel terrain; Terraria is the anti-pattern for you (finite world fully generated upfront into one .wld). One explicit warning: Valheim's networking delegates zone simulation to the first client in the area ("zone owner") — cheap but non-authoritative, and disqualifying for a game with a real-money economy; chunk simulation and persistence must live on your server.

Pixel-art pipeline at scale (4): Aseprite's CLI is built for CI — `--batch --sheet --data --format json-hash --split-tags --filename-format` exports atlases plus per-tag frame metadata, and `--palette` chains produce palette-swap variants in one command; a build step can emit both client animation data and server hitbox data (per-frame collision boxes keyed to the same tags/frames) from a single source of truth. For reskinnable creature archetypes (quadruped, biped, winged, dragon, giant, spirit), the trade-off is: hand-drawn frames are crispest but scale linearly with creatures; Spine gives rig/animation reuse and skins/attachment-swaps but its interpolation breaks pixel-grid crispness unless you use stepped keys and snap to a low-res render; Dead Cells' pipeline (cheap 3D rigs, pose-to-pose keyframes, rendered tiny with no antialiasing plus toon shading and exported normal maps) is the proven industrial answer — Motion Twin explicitly credits rig/animation reuse across characters with saving hundreds of hours. The synthesis that fits a weekly-drop cadence: one shared rig per archetype (Spine or 3D), baked at build time to plain frame atlases so the runtime stays simple frame-based sprites, plus a greyscale/indexed + LUT palette shader (standard, cheap technique with mature Godot implementations) for elemental/rarity recolors generated at runtime rather than as assets.

Economy integrity with real-money items (5): Documented dupe post-mortems (MU Online analysis, New World 2021, OSRS Oct 2024) show nearly all dupes are timing/persistence races — double-save across server handoffs, trade-state confusion, save-on-disconnect ordering, lag-abused netcode — so the defenses are structural: every item instance gets a GUID enforced unique at the database level, item state transitions (owned/listed/escrowed/consumed) go through a server-side state machine, and any transfer is a single ACID transaction in one authoritative database (never dual-writes across game servers). Layer on an append-only item event ledger (mint, trade, list, consume, destroy, with actor and timestamp) giving full provenance — this makes duplication automatically detectable (same GUID alive twice) and enables surgical, ledger-replay rollbacks of tainted items and their descendants instead of whole-server rollbacks. The money side should be a proper double-entry ledger with idempotency keys, escrow/inflight accounts, and a fee account — the marketplace flow is: item moves to escrow state, Pix payment confirms, then one atomic settlement posts money entries and transfers the item. Operationally, the industry playbook is: pre-built kill switches for every wealth-transfer vector (Amazon disabled all New World trading during its dupe; Jagex locked all OSRS trading within ~15 minutes of the 2024 potion-storage dupe, then rolled back; RuneScape did another emergency rollback in April 2026 after a game-jam update duped runes), plus continuous mint-rate anomaly monitoring. Finally, Diablo 3's real-money auction house (2012–2014) is the standing design warning: a studio-fee RMT marketplace legitimized trading but inverted the loot loop so buying beat playing, and Blizzard removed it — your itemization must be designed so the marketplace is a complement to play, not a substitute.

## Recommendations
- Define every item/creature/skill/biome as pure data with stable string IDs and PoE-style indirection (separate stat, modifier, and tag tables with spawn weights) so weekly drops are data rows; compile one canonical content repo into both the server build and client packs, and enforce a content-version hash at login so server and client never disagree on stats.
- Ship weekly drops as content-addressed PCK patches loaded via ProjectSettings.load_resource_pack(), leaning on Godot 4.6's partial-resource patch system for small downloads; never allow scripts in downloaded content (treat runtime-loaded .tres as untrusted — prefer JSON for anything fetched from the network), and keep balance numbers server-readable so hotfixes need no client patch.
- Do not force a full ECS onto the Godot client: use Resource-based composition for definitions, thin nodes for interactive entities, and RenderingServer/MultiMesh + PhysicsServer2D direct APIs for projectiles and mob crowds; put the authoritative combat/world simulation in a headless, data-oriented server process written in a compiled language (GDExtension C++/Rust or standalone; ECS is appropriate there), with Godot clients rendering replicated state.
- Architect the world as: deterministic seeded layered noise with constant-time random access; server-side on-demand chunk generation; Valheim-style persistence (store only deltas — loot taken, terrain modified, structures — against a regenerable base) inside Minecraft-Anvil-style region files (grouped chunks, sector index, compressed records); stamp every generated chunk with a generator version so weekly biome drops apply to ungenerated space with seam blending (scattered-point/domain-warped Voronoi blending avoids grid artifacts).
- Explicitly reject Valheim's client zone-ownership model: with a real-money economy, chunk simulation, entity state, and persistence must be fully server-authoritative — budget server capacity for interest-managed chunk streaming per player.
- Build 6 shared archetype rigs (quadruped, biped, winged, dragon, giant, spirit) animated once — via Spine with stepped keys or a Dead Cells-style low-poly 3D rig rendered to unfiltered low-res frames — and bake to frame atlases in CI so the runtime is simple frame-based sprites; generate recolor variants with a greyscale/indexed + palette-LUT shader at runtime instead of exporting recolored assets.
- Automate the art pipeline with Aseprite CLI in CI (--batch --sheet --data json --split-tags --filename-format, --palette chains for authored variants) and make the exported per-tag/per-frame JSON the single source of truth for both client animations and server-side per-frame hitbox data.
- Give every item instance a GUID with database-enforced uniqueness; route all state changes through a server-side item state machine (owned/listed/escrowed/mailed/consumed); execute every transfer as a single ACID transaction in one authoritative economy database; enforce single-session-per-account and correct save-ordering on disconnect and server handoff (these races caused nearly every historical dupe).
- Maintain an append-only item event ledger (mint/trade/list/consume/destroy with actor, timestamp, cause) for full provenance, and a separate double-entry money ledger with idempotency keys and escrow (inflight) accounts; marketplace settlement = item to escrow → Pix confirmation → one atomic posting that moves item, seller proceeds, and studio fee; reconcile the two ledgers continuously.
- Before launch, build the incident playbook proven by New World and OSRS: one-click kill switches for every wealth-transfer vector (trade, marketplace, mail, drop-to-ground, guild banks), mint-rate anomaly alerts on every item/currency source, and a rehearsed targeted-rollback procedure that traces tainted items and descendants through the ledger rather than rolling back whole servers.
- Heed the Diablo 3 RMAH lesson in itemization design: bind top-tier chase items or gate marketplace supply (e.g., trade counts, account-bound crafting steps) so buying power never dominates the kill-and-loot loop that retains players, since the studio-fee marketplace creates the same incentive structure Blizzard had to remove in 2014.

## Caveats
- Noita specifics beyond 64×64-pixel chunks, dirty rectangles, and multithreading (exact persistence-to-disk and streaming details) come from summaries of the 2019 GDC talk, not a full transcript — verify against the talk video before copying the design.
- Godot 4.6's partial-resource patch system and LibGodot shipped in January 2026 and have limited production track record; test the PCK patch flow (including resource replacement edge cases and script stripping) before committing weekly drops to it.
- GGG's internal league pipeline is not publicly documented; the ~3-4-month cadence is confirmed but claims about their parallel team structure are anecdotal — the transferable, verified pattern is the data-table content architecture, not the org design.
- ECS performance benefits only materialize in compiled languages; GDScript ECS frameworks are organizational. The recommended split-architecture (Godot client + compiled headless sim server) adds real engineering cost for a small studio and no public benchmark covers this exact 2D ARPG workload — prototype server chunk-simulation costs early.
- Valheim-style delta persistence assumes the base world is always regenerable from seed + generator version; every weekly generator change must be versioned and regression-tested for determinism (a floating-point or ordering change silently corrupts world consistency across versions and platforms).
- Economy-integrity findings cover architecture only: Brazilian legal/regulatory exposure of a studio-fee real-money item marketplace settled via Pix (payment institution licensing, consumer law, tax, AML/KYC, chargeback-equivalent fraud on Pix) was out of this track's scope and needs separate legal research.
- The Diablo 3 RMAH failure was game-design, not technical — no amount of ledger integrity fixes an itemization loop where buying beats playing; this risk is inherent to the studio's monetization premise and should be validated with players before building the marketplace.
- The April 2026 RuneScape rune-duplication rollback report comes from a low-profile outlet (gaminghq.eu) and secondary coverage; the OSRS October 2024 potion-storage dupe lockdown/rollback is the better-documented case to cite.
- Spine's interpolation vs pixel-grid crispness trade-off is well documented, but whether stepped-key skeletal output meets this studio's 'high-fidelity retro' bar is an aesthetic judgment requiring an art test of all three pipeline options on one archetype.
